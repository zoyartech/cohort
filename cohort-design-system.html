00 — Premise

One system, two writing systems, two light conditions

This is an atomic design system built for an internal learning platform serving early-career designers. It was authored for North America in English and scaled to India in Hindi. The architecture treats theme and script as two independent axes rather than one "localisation" flag — which is the decision everything else in the system hangs off.

The load-bearing distinction — and it is not the one people expect. Hindi is left-to-right. There is no mirroring in this project, no bidi layer, no dir switch. That is precisely what made it hard: none of the usual internationalisation reflexes fire. Nothing looks obviously broken, so nothing gets caught.

What actually breaks is the type ramp. Devanagari sets matras above and below the shirorekha, so the same pixel size reads optically smaller and crowds vertically; tight Latin heading leading clips the matras outright; and negative letter-spacing — standard practice on Latin headings — pulls conjuncts apart and changes what the word says. A system that only has a light/dark axis ships all of that to production and calls it done.

The two axes

Axis 1 · Theme

data-theme

light · dark. Swaps Tier 2 colour aliases and the elevation strategy. Zero component code changes.

Axis 2 · Script

data-script

latin · deva. Swaps font family, size multiplier, line-height set, tracking rules, minimum touch target and paragraph rhythm.

Not an axis · Direction

dir

Both shipped locales are LTR, so no mirroring layer exists. Logical properties are used throughout anyway — as engineering hygiene, not as a delivered feature. See §07.

2 themes × 2 scripts = 4 shipped surfaces. The axes never reference each other, so adding a third script is a token-block addition and a type audit — not component work.

01 — Token architecture

Three tiers, one direction of reference

Tiers reference downward only. A component may never reach past Tier 2 to a raw hex. This is the rule that made the India rollout a token-file change rather than a component rewrite.

Tier 1 · Primitive

--p-brand-600: #3B4CC4

Raw value. Carries no meaning and no mode. Renamed only when the palette itself changes. Never referenced by a component.

Tier 2 · Semantic

--c-action-primary-bg

Role, not appearance. Resolves differently per theme. This is the only tier a component is allowed to see.

Tier 3 · Component

--btn-pad-i

Local to one component, exposed for controlled override by size/variant modifiers. Never used cross-component.

Naming grammar

TierPatternExample
Primitive--p-{family}-{step}--p-teal-500
Semantic colour--c-{role}-{variant}-{state}--c-action-primary-bg-hover
Script metric--script-{property}--script-lh-body
Computed type--t-{step}--t-2xl
Component--{component}-{property}--btn-pad-i

-i and -b suffixes mean inline and block — never left/right or top/bottom. The naming enforces the mirroring discipline before anyone writes CSS.

03 — Space, radius, elevation

The invariants

Space and radius do not vary by script or theme. Elevation does — and that is the one place where dark mode is not a colour swap.

Space — 4px base, no half steps

Elevation

Dark mode does not lift with shadow. A drop shadow on a near-black canvas is invisible — the light source it implies does not exist. Elevation in dark is carried by surface value (canvas → surface → raised gets lighter) plus a border. The shadow tokens resolve to none at levels 1 and 2. Components never know this happened.

07 — Direction

What was not built, and why it still shaped the code

Both shipped locales are left-to-right. There is no mirroring layer in this system, no bidi handling, no dir switch, and no RTL locale in production. Saying so plainly is worth more than a capability claim nobody asked for.

Logical properties were used anyway. No left, right, margin-left, padding-right, text-align:left, or border-left appears anywhere in the stylesheet — only inline-start/inline-end, block-start/block-end, and text-align:start. A lint rule fails the build on any physical directional property.

That was not an RTL feature. It cost nothing at authoring time, it makes the CSS read in the same vocabulary as the token names (-i for inline, -b for block), and it means the direction axis is available if a right-to-left locale is ever added — as a token block and a type audit, not a component rewrite. It is headroom, not a deliverable.

The numerals question, which is live in Hindi

Direction was not a problem. Digits were.

CaseDecisionReason
Devanagari numerals (१२३) vs Western (123)Western throughoutIndian enterprise UI, technical training content, and every learner's keyboard already use Western digits. Devanagari numerals would be a costume, not a localisation.
Module numbers, durations, percentagesOwn node, tabular figuresKept as separate spans rather than concatenated into translated strings — so a translator cannot accidentally reorder "45 min" and so the figures align in a column.
DatesLocale-formatted, never string-builtHindi month names and the DD/MM order come from the formatter, not from a template with slots.
Learner initials in avatarsDerived from the learner's own script"अनन्या" yields "अ", not "A". Forcing Latin initials onto a Devanagari name is a small erasure that reads loudly to the person it happens to.

Font pairing

Latin and Devanagari are set in two different families (Inter and Noto Sans Devanagari), never one "universal" family. The system ships only Regular, Medium and Bold because that is the intersection of weights available in both — a weight that exists in one script and not the other produces a synthesised faux-bold in the other, which on Devanagari thickens the shirorekha until conjuncts blur together. The constraint is documented on every text style so nobody "adds Semibold" later.

08 — Governance

How the system stayed alive after handoff

Contribution tiers

ChangePath
New component variantProposal → design review → a11y check → 1 release cycle
New semantic tokenRequires a documented role that no existing token covers
New primitiveSystem team only. Palette changes are versioned as breaking.
New script/localeAdd a data-script block + type audit. No component work. An RTL locale would additionally need the mirroring exception matrix written before any build.

Definition of done

  • Renders correctly in light and dark
  • Renders correctly in Latin and Devanagari
  • No physical direction properties (lint-enforced) — headroom, not a shipped feature
  • Zero physical direction properties (lint-enforced)
  • All text pairs ≥ 4.5:1; large text and non-text ≥ 3:1
  • Keyboard-reachable with a visible focus ring in both themes
  • Hit target ≥ --script-min-touch for the active script
  • Longest translated string tested at 130% of English
